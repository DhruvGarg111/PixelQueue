# Database Migrations Guide (Alembic)

PixelQueue uses **Alembic** alongside SQLAlchemy to manage schema evolution. Database changes are tracked as code revisions inside `/api/alembic/versions`.

---

## ⚙️ Configuration & Architecture

Alembic reads configuration from `/api/alembic.ini` and executes code inside `/api/alembic/env.py`.

*   **Dynamic Connection**: `env.py` intercepts SQLAlchemy connection DSN and injects the `DATABASE_URL` environment variable at runtime.
*   **Metadata Source**: The target metadata is bound directly to the declarative base model:
    ```python
    from app.models.base import Base
    from app.models import entities  # Imports tables to register metadata
    target_metadata = Base.metadata
    ```
*   **Type Comparison**: Alembic is configured to detect database column type adjustments by setting `compare_type=True`.

---

## 🛠️ Operational Workflows

### 1. Generating a New Migration
When database models are modified in `api/app/models/entities.py`, generate a new migration file:

```bash
# Executing inside the API container context
docker compose exec api alembic revision --autogenerate -m "describe_your_changes"
```

*   **Validation**: Check the generated python file inside `/api/alembic/versions/`. Ensure foreign key constraints, nullable options, and index parameters are correctly translated.

### 2. Applying Migrations
To upgrade the database to the latest schema revision:

```bash
# Executing inside the API container context
docker compose exec api alembic upgrade head
```
*Note: In the Docker Compose environment, this command is executed automatically on container start during the entrypoint sequence.*

To upgrade by a specific number of versions:
```bash
docker compose exec api alembic upgrade +1
```

### 3. Rolling Back Migrations
If a deployment fails, or you need to undo changes during development:

```bash
# Rollback the last migration
docker compose exec api alembic downgrade -1

# Rollback to the baseline bootstrap schema
docker compose exec api alembic downgrade base
```

### 4. Checking Migration History
To view the list of applied and pending migrations:

```bash
# View active database version
docker compose exec api alembic current

# View history of all revisions
docker compose exec api alembic history --verbose
```

## 📝 Migration Best Practices

1.  **Always Review Autogenerated Files**: Alembic's autogenerate function does not reliably detect table rename operations (it translates them as table drops and adds, causing data loss). Review code blocks manually before committing.
2.  **Avoid Raw SQL Strings**: Use SQLAlchemy SQL expression primitives inside the `upgrade()` and `downgrade()` code blocks to remain database engine-agnostic:
    ```python
    # Recommended
    op.add_column('users', sa.Column('last_login', sa.DateTime(timezone=True)))
    ```
3.  **Specify Cascades**: When adding foreign keys, always declare delete behaviors explicitly (e.g. `ondelete="CASCADE"` or `ondelete="SET NULL"`) to avoid orphan records.
4.  **Do Not Import Models**: Never import Pydantic schemas or SQLAlchemy model classes directly inside migration files, as their code structure will drift over time. Use literal strings for table and column declarations.
